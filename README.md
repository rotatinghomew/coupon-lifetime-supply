# 防护贴老化挑批资料交换

`data/` 收录供演练使用的合成记录，不含真实企业或人员资料。资料使用 UTF-8 逗号分隔，首行为字段名，带逗号的单值用双引号括起。日期采用 ISO 表示，空字段表示来源未填或不适用，不代表数值零。`sources.json` 记录各表列名、身份键和可直接核对的引用。

## 业务资料

- `inventory.csv`：当前批次有共同生产批、数量、入库龄、合同用途限制。时间均以天为单位。
- `observations.csv`：检测窗口是贴片年龄；失效落在前次已确证正常与首次确证失效之间，未观察至终点留空。sample_prob 是该来源抽到该片的概率。
- `contracts.csv`：duration 是到达后保障时长，risk_limit 是整个使用段可接受的失效风险；family_cap 是同生产家族数量上限。
- `warranty.csv`：合同保修界线。它影响申诉覆盖，不改物理失效。
- `picks.csv`：已确认和出库的持有关系。不存在的确认不得被当作既有约束。
- `rechecks.csv`：复查窗口容量，用 lot_options 约束可处理的库存。
- `lab_options.csv`：复查动作的抽走件数、能覆盖的检查龄及结果返回时点。未来值不得当成现有事实。
- `supplemental.csv`：有实际现场回执的复查记录。received 是批备货时钟上的到达时点。
- `historical_orders.csv`：冻结的历史挑批依据和订单使用结果，shipment_age 包含在途年龄；尚未收齐的结果不当成持续完好。

last_seen 是最后能确认观察状态的龄期，seen_on 是记录可用的日期；同一试件最后收到的行替代旧观察记录。数量是可用单件数；备用抽查会实际占住这些件。保障时长从抵达日计，库存 age 以相应 available_at 为基准。合同允许混装时，可并用兼容批但仍要受同家族上限约束。

## 分析包 `aging/`

在交换资料之上实现了一套可复核的老化挑批核对，纪律如下：

- **时间事实**：失效只知道夹在 `last_ok` 与 `first_failed` 之间，按区间删失入似然；未失效件在 `last_seen` 右删失，`sold/replaced/returned_other/monitoring` 分开计数，`--pessimistic` 可把前三类当作窗内可能失效的敏感性口径。
- **左截断与抽样**：试件在 `entry_age` 才进入观察，似然以"活到 entry_age"为条件；`sample_prob` 做逆概率加权并报告有效样本量（ESS），不把权当件数。
- **证据层级**：同家族直配 → 当前生产线同层池化（试件 <8 标记为薄池化，不能单独放行）→ 含参考线的全层池化/参考家族池化（仅参照，不能放行）→ 不可估计。humid 与 normal 等条件永不混线。
- **模型选择**：主模型是指数恒定风险（小样本区间删失下经验校准最稳），Weibull 保留为形状敏感性对照，Turnbull 非参估计用于识别观察支撑龄期。冻结时点回看 31 张历史订单，段风险 UCB95 经验覆盖率约 0.97。
- **判定口径**：以合同使用段（抵达龄期到保障期末）的条件失效风险对 `risk_limit`，点估计超限即不合格，点估计达标但自助 UCB95 超限为临界；质保界线只影响申诉覆盖，不进入物理风险。
- **复查**：抽离件立即从可发库存扣除；未观测动作只展开通过/不通过分支，同一假设结果不能同时保证两个竞争合同；回执按 Jeffreys 二项后验与生存证据融合，且只覆盖到 `tested_age`，超出部分不外推；回执晚于合同发运日只更新现行解释与客户提示，不撤销出库、不改旧时点预测。
- **分配**：`family_cap` 同家族上限、`mix_allowed=0` 单批约束、已确认持有（含已发运）均为硬约束；输出不复查与各复查安排的可行集、分支触发条件与替代决定截止时点。
- **回看**：每张历史订单只用其 `asof` 当日及之前的证据（先按时点过滤再去重，防止后见之明），`consumed < qty` 的未收齐件不计为完好。
- **复用**：`--review` 从合同视角列出每个匹配批的可选性与互斥不可选原因（承诺占用、复查抽离、证据太薄、仅参考证据、风险超限、临界等）。

## 本地核对

需要 Python 3.11。分析环境可使用 `python3 -m pip install -r requirements.txt` 安装锁定的数值依赖。

从仓库根目录执行 `python3 check_sources.py`，返回各表行数；其他同格式资料可用 `python3 check_sources.py 路径` 检查。脚本只读资料并报告结构或引用错误，不给出业务结论。执行 `python3 -m unittest discover -s tests -v` 检查资料约定、拒绝重复身份、生存估计、时点泄漏、复查融合与分配约束。

## 分析入口

```
python3 run_analysis.py                      # 默认时点 day 1，比较不复查与各单项复查
python3 run_analysis.py --asof-day 7         # 切到更晚证据时点，迟到回执按规则融合
python3 run_analysis.py --plans T1 T3        # 指定复查组合（每个参数是一组方案）
python3 run_analysis.py --pessimistic        # 悲观删失敏感性口径
python3 run_analysis.py --backtest           # 追加冻结时点回看校准
python3 run_analysis.py --review --json out.json   # 库存回看 + 机读 JSON
```

人读报告包含证据基础与可比性、质保界线、各复查安排可行性、段风险点估计/UCB、未观测分支、覆盖提醒、重复占用核对、替代决定截止时点与已出库客户提示；机读 JSON 字段与报告一一对应。
